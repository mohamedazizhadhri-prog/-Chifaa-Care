┌─────────────────────────────────────────────────────────────────────┐
│  OLD CODE (Buggy) ❌                                                 │
└─────────────────────────────────────────────────────────────────────┘

const conflictingAppointment = await prisma.appointment.findFirst({
  where: {
    doctorId,
    appointmentDate: {
      lte: endTime,              // ❌ Too broad
    },
    endTime: {
      gte: appointmentDate,      // ❌ Too broad
    },
    status: {
      in: ['PENDING', 'CONFIRMED'],
    },
  },
});

Problem: This query finds appointments where:
  - Start is before or equal to requested end
  - End is after or equal to requested start

This is too broad and catches non-overlapping appointments!

Example of FALSE POSITIVE:
  Existing: 08:00-09:00
  Requested: 10:00-11:00
  
  Query checks:
    08:00 <= 11:00 ✓ (TRUE)
    09:00 >= 10:00 ✗ (FALSE)
  
  Result: No conflict (correct by luck)
  
  But with different times:
  Existing: 09:00-10:00
  Requested: 10:00-11:00
  
  Query checks:
    09:00 <= 11:00 ✓ (TRUE)
    10:00 >= 10:00 ✓ (TRUE)
  
  Result: CONFLICT! ❌ (WRONG - these are adjacent!)

┌─────────────────────────────────────────────────────────────────────┐
│  NEW CODE (Fixed) ✅                                                 │
└─────────────────────────────────────────────────────────────────────┘

const startDate = new Date(appointmentDate);
const endDate = new Date(endTime);

const conflictingAppointment = await prisma.appointment.findFirst({
  where: {
    doctorId,
    status: {
      in: ['PENDING', 'CONFIRMED'],
    },
    AND: [
      {
        appointmentDate: {
          lt: endDate,           // ✅ Strictly less than
        },
      },
      {
        endTime: {
          gt: startDate,         // ✅ Strictly greater than
        },
      },
    ],
  },
});

Solution: This query finds ACTUAL overlaps where:
  - Existing starts BEFORE requested ends (lt, not lte)
  - Existing ends AFTER requested starts (gt, not gte)

This is the correct overlap detection algorithm!

Example - Adjacent (No Conflict):
  Existing: 09:00-10:00
  Requested: 10:00-11:00
  
  Query checks:
    09:00 < 11:00 ✓ (TRUE)
    10:00 > 10:00 ✗ (FALSE) ← This saves us!
  
  Result: No conflict ✅ (CORRECT - adjacent is OK!)

Example - Overlap (Real Conflict):
  Existing: 09:30-10:30
  Requested: 10:00-11:00
  
  Query checks:
    09:30 < 11:00 ✓ (TRUE)
    10:30 > 10:00 ✓ (TRUE)
  
  Result: CONFLICT! ✅ (CORRECT - real overlap!)
